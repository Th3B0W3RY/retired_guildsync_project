**Controller:** `guildsync/app/controllers/admin/dashboard_controller.rb` — `GET /admin` (`admin_root_path`). **`Turbo-Frame: admin_dashboard_index_main`** → **`dashboard_index_frame`** (**`layout: false`**); page **`h1`** (`admin.dashboard.title`) stays outside the frame. **`_dashboard_main`** wraps stats, pending-games banner, quick actions, and critical-feature tiles; links use **`data-turbo-frame="_top"`** so visits to other admin pages replace the full document, not the frame (**mega #218**). **Lane B checkpoint (2026-04-06):** tracked admin **`GET`** Turbo / results-frame inventory is complete through **mega #235**; historical program status and coordination notes now belong in `guildsync_knowledge_base`. **`Admin::BaseController`** uses **`# frozen_string_literal: true`** (same as other **`Admin::*`** controllers).

**Admin login (`GET /admin/login`):** `Admin::SessionsController` uses the normal `application` layout. The credential form lives in **`turbo-frame`** **`admin_sessions_login_main`** (**`_sessions_new_main`**). The frame responder is **frame-id agnostic**: any incoming **`Turbo-Frame`** header is echoed back by `sessions_new_frame`, which prevents Turbo **“Content missing”** when `/admin/login` is loaded inside another admin frame. The login form uses **`data-turbo="false"`** so the browser performs a classic POST (avoids Turbo-fetch + session/CSRF edge cases; success still **`redirect_to`** admin root). **`ADMIN_PASSWORD`** and **`ADMIN_EMAIL`** are **`.strip`**’d when read from ENV so Docker/K8s/env-file trailing newlines do not make correct passwords look “broken” (failed logins return **422** with **`admin.sessions.invalid_credentials`**). **`flash[:alert]`** is rendered above the form so Turbo-frame failure responses show the error. If a **member** is already signed in, layouts set `admin_sessions_shell` (compact nav, no member sidebar). **Specs:** `spec/requests/admin/sessions_spec.rb`.

## Flash toast settings (related)

- **Routes:** `GET/PATCH /admin/settings/flash` (`admin_flash_settings`, `admin_update_flash_settings`), `POST /admin/settings/flash/test` (`admin_test_flash_settings`) — see `config/routes.rb` under `namespace :admin`.
- **Controller:** `Admin::FlashSettingsController` — updates `SiteSetting` key `flash_toast_duration_ms` (clamped **500–60_000** ms; default **2500**); test action sets `flash[:notice]` / `alert` / `warning` / `info` and redirects back. **`Turbo-Frame: admin_flash_settings_main`** → **`flash_settings_show_frame`** (**`layout: false`**); page title + back link stay outside the frame. **`flash_settings_refresh`** / **`flash_settings_flash_only`** Turbo Stream targets unchanged (**mega #215**).
- **Persistence:** `SiteSetting.flash_toast_duration_ms` — invalid or out-of-range stored values fall back to default.
- **UI wiring:** `ApplicationController#flash_toast_duration_ms` (helper) → `shared/_toast_flash_host` `data-toast-default-ms-value` → Stimulus `toast` controller `defaultMs` value.
- **Specs:** `spec/requests/admin/dashboard_spec.rb`; `spec/requests/admin/flash_settings_spec.rb`; `spec/models/site_setting_spec.rb` (`flash_toast_duration_ms`). Broader admin coverage: `spec/requests/admin/*_spec.rb`.
