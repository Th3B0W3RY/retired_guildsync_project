# Internationalization (i18n)

**Last updated:** 2026-05-19 — **DEV-190** mixed locale on `/login`, **`zh.yml`** structure, Devise **`parent_controller`**, **`GS_LOCALE_DEBUG`**, **`public_page?`** (confirmations, **`controller_path` sessions)

## Locales

Ten locales, aligned across **`config/application.rb`**, **`config/i18n-tasks.yml`**, and **`MEGA`** / product rules: **en, de, es, fr, it, ja, ko, pt, ru, zh**.

| Setting | Location | Value |
|---------|----------|--------|
| **`available_locales`** | **`config/application.rb`** | **`[:en, :de, :es, :fr, :it, :ja, :ko, :pt, :ru, :zh]`** |
| **`default_locale`** | **`config/application.rb`** | **`:en`** |
| **`fallbacks`** | **`config/application.rb`** | **`true`** |
| **`load_path`** | **`config/application.rb`** | **`config/locales/**/*.{rb,yml}`** |

Files live under **`config/locales/{locale}/`**. Use routed breakout files first (e.g. **`models.{locale}.yml`**, **`devise.{locale}.yml`**, **`home.{locale}.yml`**, **`guilds.{locale}.yml`**, **`admin.{locale}.yml`**, **`javascript.{locale}.yml`**). Keep **`{locale}.yml`** as fallback/catch-all for namespaces without a dedicated breakout.

## Runtime locale resolution (`ApplicationController#set_locale`)

Order (**first match wins**):

1. **`locale_from_param`** — **`params[:locale]`** if in **`I18n.available_locales`**; persists **`session[:locale]`**.
2. **`locale_from_user`** — Signed-in: **`current_user.preferred_locale`** if present. If signed-in but preference blank, returns **`nil`** (does **not** use **`session[:locale]`** — avoids stale **`?locale=`** overriding “Default” in settings). Guests: **`session[:locale]`** if valid.
3. **`locale_from_browser`** — **`http_accept_language.compatible_language_from`**, **unless** signed-in with blank **`preferred_locale`** (then skip browser so the app stays on **`:en`** until the user picks a language).
4. **`I18n.default_locale`**

**`SettingsController#update_locale`** updates **`preferred_locale`**, clears **`session[:locale]`**, sets **`I18n.locale`** for the current request (see **`authentication_mfa.md`**).

## RCA: mixed Chinese / English on `/login` (DEV-190, 2026-05)

**Symptoms:** `<html lang="zh">`, language switcher **中文**, Chinese strings for **`sessions.new.*`** / nav / banner while **Email**, **Password**, **Sign In** stay English (production matches **`sessions/new`** using **`common.labels.*`** + **`common.buttons.sign_in`**).

**Root causes:**

1. **`config/locales/zh/zh.yml`** — **`account_creation:`** was dedented to **YAML column 0** (sibling of **`zh:`** instead of nested under it). The parser nested **`api`**, **`common`**, **`gear`**, etc. under **`account_creation`**, so **`zh.common.*`** was missing → **`config.i18n.fallbacks`** → English for those keys while **`sessions.*`** (e.g. in **`auth.zh.yml`**) still resolved in Chinese.

2. **`Devise`** **`parent_controller = ActionController::Base`** — **`SessionsController`** did not run **`ApplicationController#set_locale`**, so **`Accept-Language`** and guest/session locale behavior diverged from the marketing shell.

**Fixes:** **`zh.yml`**: nest **`account_creation`** under **`zh:`**, **`zh.common.buttons.create_account`** → **创建账户**. **Other locales (`de`, `es`, `fr`, `it`, `ja`, `ko`, `pt`, `ru`)**: same **`account_creation`** dedent bug in catch-all **`{locale}.yml`** — repaired (parity with **`en/en.yml`**); removed duplicate English **`api.auth`** rows that overwrote localized strings. **`Devise`** **`parent_controller`** → **`ApplicationController`**. **`public_page?`**: **`confirmations`** + **`controller_path == "sessions"`** for guest **`new/create`**. **`SessionsController`**: **`ensure_fully_authenticated`** skip on **`destroy`**; localized login rescue via **`User.human_attribute_name(:email)`**. Layouts: drop English **`default:`** on **`common.buttons.create_account`**.

## Incident triage (reporters)

- Confirm locale (**`zh`** vs **`ja`** vs **`ko`**), URL, signed-in vs guest, browser; disable **Chrome Translate** when verifying server-rendered language.
- **View source:** `<html lang="...">` and snippets around mixed strings.
- Guests: **`session[:locale]`** wins over **`Accept-Language`** until cleared — stale **`?locale=`** causes apparent “random” switches.

## `sessions#create` vs `set_locale`

**`set_locale`** runs **before** **`SessionsController#create`** completes sign-in; **`current_user`** may still be nil on that POST — guest rules apply; next GET uses signed-in rules.

## Observability: `GS_LOCALE_DEBUG`

When **`ENV["GS_LOCALE_DEBUG"] == "1"`**, HTML responses include headers (**off in test**): **`X-GuildSync-Locale`**, **`X-GuildSync-Session-Locale`**, **`X-GuildSync-Params-Locale`**, **`X-GuildSync-Accept-Language`** (truncated), **`X-GuildSync-User-Preferred-Locale`**, **`X-GuildSync-Controller-Action`**. Allowed in **`development`** / **`Rails.env.staging?`**; production only if **`ENV["GS_LOCALE_DEBUG_PRODUCTION_OK"] == "1"`** (short RCA only).

## Product note

Guests follow **`Accept-Language`** when no sticky **`session[:locale]`**. Alternative (not implemented): force **`en`** on auth/marketing until the user picks a language.

## `i18n-tasks` (`config/i18n-tasks.yml`)

- **`base_locale: en`**
- **`locales:`** list must match **`config.i18n.available_locales`**.
- **`data.router: pattern_router`** — **`write`** rules are **first match wins**; **`config/locales/%{locale}/%{locale}.yml`** is the **fallback catch-all** last line.
- **Add a new prefix rule above the catch-all** when introducing a new top-level key namespace, or **`i18n-tasks normalize`** / **`missing`** will target the wrong file.
- Notable routed trees: **`js.*`** → **`javascript.{locale}.yml`**; **`admin.*`** → **`admin.{locale}.yml`**; **`alliances.*`**, **`alliance_*`**; **`roadmap.*`**; **`devise.*`**; **`errors.attributes.user.one_account_per_ip`** → **`devise.{locale}.yml`**; **`activerecord.models.*`**, **`activerecord.attributes.*`**, **`activerecord.errors.models.*`**, **`ocr.messages.*`** → **`models.{locale}.yml`**.
- **`ignore_missing`** includes Rails-i18n **`number.*`**, **`time.*`**, **`date.*`**, **`errors.*`**, etc.
- **`missing.consider_fallbacks: false`** — stricter: keys missing in a locale are reported even if English exists.

**Commands** (from **`guildsync/`**): **`bundle exec i18n-tasks missing`**, **`bundle exec i18n-tasks health`**.

## Workflow for new user-facing strings

1. Add the English key in the file implied by **`i18n-tasks`** routing (prefer breakout files; avoid defaulting to **`en.yml`** unless the namespace is truly catch-all).
2. Mirror the **same key path** in all **9** other locale files (product expectation: real translations where possible).
3. Run **`bundle exec i18n-tasks missing`** before merge.
4. Use **`t('key')`** / **`I18n.t`** in views and controllers; avoid raw user-facing literals.

## Common pitfalls

- **`zh.yml` / locale catch-alls:** Every key must nest under **`zh:`** (or **`en:`**, **`ja:`**, …). A **dedented** key at column 0 (e.g. **`account_creation:`**) becomes a separate root and can swallow **`common`**, **`api`**, etc. **`de/de.yml`** through **`ru/ru.yml`** had the same mistake historically — diff structure vs **`en/en.yml`** after edits.
- **OAuth gated signup flash** — Use **`account_creation.gated_oauth.verify_first`** for “finish email + backup before social sign-in” (shared by Discord, Gmail, Outlook). **`controllers.oidc_user_auth`** holds Gmail/Outlook-only errors (**`invalid_state`**, **`email_mismatch`**, etc.); avoid **`controllers.discord_user_auth`** for OIDC callbacks.
- **YAML 1.1:** Unquoted **`yes`** / **`no`** keys parse as booleans — quote them (**`"yes":`**, **`"no":`**). Applies to e.g. **`admin.feature_abusers`** and **`polls`**.
- **Duplicate keys** in large YAML — last wins; grep before adding.
- **Pluralization** — for **`count`**, supply **`one`** / **`other`** (and **`few`**/**`many`** where **RU** etc. need them).
- **JavaScript** — strings under **`js.*`** → **`javascript.{locale}.yml`**; see **`javascript_admin_dashboard_spec`** and related request specs.

## Spec pointers

Locale-aware UI is enforced indirectly: many **`spec/requests/*_spec.rb`** examples use **`locale: :de`** (or other) and assert **`I18n.t`** / body content. There is no dedicated **`i18n_tasks_spec`** in-tree; **`i18n-tasks`** is the CI/pre-commit gate.
