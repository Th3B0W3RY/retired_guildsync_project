# Content moderation

**Last updated:** 2026-04-06 (index Turbo Frame main — **mega #234**; health/profanity tab Turbo Streams — **mega #190**)

**Admin:** `Admin::ContentModerationController` — index, approve/hide/soft-delete, blocked words, profanity trigger, health check. **`GET …/content_moderation`:** **`CONTENT_MODERATION_INDEX_MAIN_FRAME`** = **`admin_content_moderation_index_main`**; **`admin_content_moderation_flash`** outside the frame; **`content_moderation_index_frame`** (**`layout: false`**) when **`Turbo-Frame`** matches; tab links target the frame for in-page tab switches. **Turbo Streams (mega #185, #187, #190):** pending queue **`content_moderation_refresh`**; blocked words **`content_moderation_blocked_words_refresh`**; **POST** **`run_health_check`** / **`trigger_profanity_update`** → **`content_moderation_health_refresh`** / **`content_moderation_profanity_refresh`** (flash **`admin_content_moderation_flash`**, wraps **`admin_content_moderation_health_wrap`** / **`admin_content_moderation_profanity_wrap`**, partials **`_health_panel`**, **`_profanity_list_panel`**). **i18n (mega #126):** controller flashes use **`admin.content_moderation.flash.*`** in **10** **`admin.{locale}.yml`** files (index load error, approve/hide/soft-delete, blocked-word messages, health/profanity queue notices). **`run_health_check`** calls **`ContentModerationHealthCheckJob.perform_async`** (Sidekiq `Worker`, same as the 6-hour scheduler — not ActiveJob **`perform_later`**). **Models:** **`FeatureRequest`** / **`FeatureRequestComment`** **`apply_content_moderation`** skips on **update** when the user-visible text columns did not change (`title`/`description` or **`body`**), so admin-only moderation updates (e.g. **hide** → **`rejected`**) are not overwritten by a re-scan that would set **`approved`** for clean copy. **Tests:** `spec/requests/admin/content_moderation_spec.rb` — **POST run_health_check** / **`trigger_profanity_update`** **`perform_async`**; **`.turbo_stream`** → health / profanity wrap ids (**mega #190**); authenticated **approve** / **hide** / **soft_delete** happy paths; **authentication** examples for unauthenticated **index** and all mutating actions → **`admin_login_path`** without side effects where asserted.  
**Public guild listing:** `Guild#publicly_listed` + recruiting slug filter — hide from directory when name matches blocked terms (`RecruitingVisibilityService`). **Create guild** (`guilds/new`) shows a live warning when the typed name would be hidden; the same logic runs in `before_validation :apply_recruiting_visibility_for_name` on create. **Tests:** `spec/services/recruiting_visibility_service_spec.rb` (string vs `Guild`, case folding, every `BLOCKLIST` entry); `spec/models/guild_spec.rb` (`publicly_listed` on save); `spec/requests/guilds_spec.rb` (`recruiting_name_warning`).

**Feature requests / comments:** `ContentModeration::FilterService` on `FeatureRequest` and `FeatureRequestComment` (`before_validation`); **`RecruitingVisibilityService.matching_severe_terms`** on title/description/body adds the same **severe** substring list as public recruiting (`BLOCKLIST`: e.g. nazi, hitler, kkk, slur) so those terms queue for review even if absent from the profanity list. Pending rows appear in the admin moderation queue until approved. **`RoadmapController#show`** loads comments via **`feature_request_comments.visible_to_public`** so pending comment bodies never appear on the public detail page. Request coverage: `spec/requests/roadmap_spec.rb`. See [`feature_requests_roadmap.md`](feature_requests_roadmap.md).
